# M2 hardware checklist: settings on the real controller

What M2 must show on the real machine: `webcontrol-rs` saves settings to the shared `~/.WebControl/webcontrol.json`
in a form Python reads back unchanged, writes each edited setting to the controller as Python would, and after every
controller boot pushes **every** setting (with `$13`, which sets the sprocket radius) and verifies them with `$$`. The
setup screens' sprocket, chain and motor actions run. **Some steps turn the motors.** Jobs (Play) are still M4.

Safety, for every step below:

- **Router switched off at its own switch, and the bit removed.**
- Steps 6 and 7 turn the sprockets and extend chains: the sled is supported or hanging freely with room to move, and
  you can reach the controller's power.
- Keep a hand near the UI's **Stop** button. If Stop ever fails, cut the controller's power and report it.

You need: the Mac with this branch checked out, the Pi booted from the new microSD card (`pi@maslow-next.local`), the
controller on USB (holey 51.27 on PCB v1.1), the Python service installed and working, and a browser.

Tick each box; if one fails, note what you saw, press Stop, and run `wc-switch python`.

## 1. Before you start

- [ ] On Python: connect, check "Firmware: Holey 51.27", then close the browser tab.
- [ ] Back up the settings (never edit the original): `scp -r pi@maslow-next.local:.WebControl ~/webcontrol-backup-m2/`.
- [ ] Note three values from Settings → Maslow Settings / Advanced Settings: Motor Spacing X, Rotation Radius,
      Chain Pitch. Note the time for the journal: `date`.

## 2. Install and switch (from the Mac, repo root)

- [ ] `rust/deploy.sh install` prints `Installed webcontrol-rs 0.1.0 (<commit>, contract 2) for pi.`
- [ ] On the Pi: `wc-switch rust` prints "WebControl is now the rust backend".
- [ ] On the Pi: `ls ~/.WebControl` now also shows `webcontrol.json.pre-rs`, byte-identical to the backup's
      `webcontrol.json` (`cmp` on the Mac after copying it back). It is taken once and never rewritten.

## 3. Edit a setting

- [ ] Settings → Maslow Settings: change Motor Spacing X by +1 mm and save. The form shows the new value, and the log
      viewer (`/next/logs`) shows one `Sent: $2=<new value>` and its `ok`.
- [ ] Reload the page: the new value is still there. On the Pi, `grep -A3 motorSpacingX ~/.WebControl/webcontrol.json`
      shows it, and `webcontrol.json.bak` holds the previous version.
- [ ] Type `abc` into Motor Spacing X and save: the form shows "Must be a number", nothing is sent, nothing is saved.
- [ ] Change Units on the front page (mm ↔ inches): the log shows `Sent: G20` (or `G21`), the jog step and the home
      position convert, and the change is still there after a reload.

## 4. Power-cycle the controller: the full push (the M2 "done when")

- [ ] Switch the controller's power off and on (or unplug and replug USB). Within about 10 s the log shows the boot
      banner, then `Sent: B05`, `Firmware Version 51.27`, `Sent: G21`/`G20`, `Sent: G90`, then one `Sent: $n=...` for
      every setting in key order **including `$2=<the new value>` and `$13=63.5000`**, then `Sent: $$`.
- [ ] The `$$` reply that follows lists `$2` at the new value, and no `Sent: $n=` follows it (nothing differed).
      If one does, note which key: that is a setting the controller stores differently from WebControl.
- [ ] No alarm or alert appeared, and "Firmware: Holey 51.27" is shown again.

## 5. Quick configure and the setup screens

- [ ] Actions → Quick Configure shows the kit as Python showed it (Ring or Custom, the chain side, spacing and offset).
      Save it unchanged: the log shows no `Sent: $` line for values that did not change.
- [ ] The Z-axis and sprocket screens open and show the chain extend length; the Z-limit buttons are hidden on 51.27.
- [ ] Actions → PID Tuning shows the stored gains (Kp/Ki/Kd for velocity and position) as on Python.

## 6. Motors and sprockets (motors turn)

- [ ] Diagnostics → Test Motors/Encoders: the log shows `Sent: B04`, each motor turns both ways, and the controller's
      report appears in Controller Messages.
- [ ] Sprocket setup: turn the left sprocket +5° and −5°: the log shows `G91`, `B09 L<distance>`, `G90`, and the
      sprocket moves that little.
- [ ] Automatic sprocket alignment: the log shows `B10 L`, the controller's `[Measure: ...]`, `B10 R`, its reply, then
      `G91`, `B09 L...`, `B09 R...`, `G90`, and both sprockets end with a tooth at 12 o'clock.
- [ ] Fake servo: turn it on and off; the log shows `B99 ON` / `B99 OFF` and the controller's reply to each.

## 7. Chains (only if you are re-hanging chains anyway)

- [ ] Extend the left chain: after the 5 s countdown the log shows `B02 L1 R0` then `B10 L`; when the measurement
      comes back WebControl sends `!` and the chain stops. Press Stop yourself if it does not stop at the extend length.
- [ ] Set chains to default (`B08`) only with the chains really at their extend length.

## 8. Back to Python: the shared file

- [ ] `wc-switch python`, then open Python's UI: Settings shows the edited Motor Spacing X and every other value as
      Rust left it, and Python connects and syncs without an "EEPROM" alert.
- [ ] Put Motor Spacing X back on Python (or keep it); Python saves as usual.
- [ ] `cmp ~/.WebControl/webcontrol.json.pre-rs ~/webcontrol-backup-m2/.WebControl/webcontrol.json` on a copy still
      matches.

Report: the boxes that failed, what you saw, `~/.WebControl/webcontrol-rs.log`, and
`journalctl -u webcontrol-rs --since "<the time from step 1>"`.
